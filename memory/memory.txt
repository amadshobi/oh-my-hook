Manage persistent curated memory across sessions. Use this tool to proactively save, update, or remove key project conventions, architecture decisions, user preferences, and lessons learned.

## HOW:
Make all your changes in ONE call via an `operations` array (each item: `{ action, content?, old_text?, target? }`). The batch applies atomically and the character limit is checked only on the FINAL result — so a single call can remove/replace stale entries to free room AND add new ones together.
Use the bare action/content/old_text fields only for a single lone change.

## WHEN (BE PROACTIVE):
Save proactively when the user states a preference, correction, or personal detail, or you learn a stable fact about their environment, conventions, or workflow.
Priority: user preferences & corrections > environment facts > project rules. The best memory stops the user from repeating themselves.

## TARGETS:
1. `user`: Who the user is (name, persona, language preference, developer identity, communication style).
2. `global`: Personal technical notes across repos (environment facts, CLI quirks, tool conventions).
3. `project`: Active repository rules (architecture decisions, test commands, project conventions).

## ACTIONS:
1. `add`: Save a new durable memory entry.
   - Requires: `content`
2. `replace`: Replace an existing memory entry using substring matching.
   - Requires: `old_text` (unique substring) and `content` (new replacement text)
3. `remove`: Delete an existing memory entry using substring matching.
   - Requires: `old_text` (unique substring)
4. `list`: Inspect all currently active memories across targets.

## IF BUDGET FULL:
An add is rejected with budget usage shown. Reissue as ONE batch that removes or shortens enough stale entries and adds the new one together.
